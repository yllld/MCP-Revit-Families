# Политика параметров, версия 2

Приоритет имён: **обозначение производителя → инженерная нотация**. Если на
заводском чертеже стоят A×B×H, сохраняются A, B, H. В `source.designation`
записывается исходное обозначение; план отклоняет произвольную замену A на L.
Для необозначенных размеров используются L/B/H, l1/b1/h1, d1/r1/t1, a1/x1/y1/z1.
Углы: α1 или a_ang1 (Angle). Видимость/варианты: короткое v1 (YesNo), только
с соответствующим назначением. Нестандартное обозначение производителя может
потребовать явного согласования, если оно содержит пробелы или операторы формул.

## Обычные Family Parameters

Builder принимает `spec.family_parameters`. Объявление включает `name`, `type`,
`purpose`, `used_for`, `source`, а также `value`/`unit` либо `formula`.
Используются обычные TYPE Family Parameters через AddParameter(name, group, type,
false). Shared definitions/file и GUID не создаются и не меняются. Существующий
одноимённый параметр можно использовать только при совместимом типе и отсутствии
конфликта с существующей формулой. ADSK/shared запрещены в роли параметров,
которыми Builder управляет геометрией.

Параметры объявляются только при необходимости. `used_for` явно объясняет роль:
geometry, position, formula, catalog, flex, visibility или variant. Автоматического
создания параметра для каждого размера чертежа нет. Параметры без значения или
подтверждённого расчёта отклоняются. Никакого переименования исходных параметров.

Для новой формулы нужны `source_type=derived` и точный `source.calculation`,
совпадающий с `formula`. Поддерживается арифметика +, -, *, /, скобки, объявленные
параметры и числа. Проверяются зависимости, циклы, размерность и деление на ноль.
Пример: `r1 = d1 / 2`. Независимое значение для r1 вместе с формулой запрещено.
Существующая формула никогда не заменяется. Функции Revit (if, sin и др.) пока
не входят в поддерживаемый язык новых формул. Значения и формулы проверяются
readback после Regenerate; ошибка приводит к откату TransactionGroup.

## ADSK и прочие shared parameters

Записываются только существующие параметры. Значение должно содержать `confidence`
либо иметь единственный mapping с confidence. При двух оценках используется меньшая.
`confirmed=true` не обходит порог. Правила распространяются и на shared parameters
без префикса ADSK.

| Оценка | Классификация | Действие |
| --- | --- | --- |
| ≥ 0.95 | CONFIRMED | Запись после остальных проверок |
| ≥ 0.70 и < 0.95 | REVIEW | Показать в dry-run, не записывать |
| < 0.70 или нет корректной оценки | UNKNOWN | Пропустить |

Источник должен содержать `source_type=direct`, `file` либо `reference`, `field`
либо `designation`, `origin=user_provided`, `model_match=true`. Если пользователь
разрешил внешний поиск, допускаются `origin=external` и `search_authorized=true`.
Сам confidence не доказывает достоверность: AI должен проверить исходник до
формирования спецификации. derived/user_input/integration_test не принимаются как
прямой источник информационных данных. Явное значение из текста пользователя можно
описать как direct с reference на его сообщение.

Конфликты передаются в `source.conflicts` с обоими значениями и источниками. Они
получают SOURCE_CONFLICT и не записываются. Отсутствие параметра, формула, read-only,
несовместимые данные/единицы также запрещают запись. Instance defaults по умолчанию
пропускаются. Для явного заполнения общих начальных значений экземпляров семейства
используется `write_instance_defaults=true` в спецификации. Это не
преобразует параметр в TYPE и не редактирует размещённые экземпляры в проектах.
План показывает `write_scope=family_instance_default_all_types` и `affected_types`.
Источник/confidence и все остальные проверки действуют. Различающиеся значения
одного instance-параметра для разных каталоговых типов запрещены. Записанное
значение проверяется для каждого типа; все остальные исходные значения защищены.

Числовое значение Number не трактуется автоматически как кг или другая физическая
величина по имени параметра. Для фактического Mass допустим kg, для ElectricalPower
W/kW, для ElectricalPotential V, для ElectricalFrequency Hz. Единицы остальных
типов перечислены в `core/active_plan.py`.

## Dry-run и выполнение

Отчёт разделяет `family_parameters_to_create`, `family_parameters_reused`,
`geometry_parameter_mapping`, `adsk_parameters_to_write`,
`adsk_parameters_for_review`, `adsk_parameters_skipped`. Только разрешённые записи
попадают в исполняемый `parameters_to_write`. Пропущенный ADSK не блокирует
достоверную геометрию. Ошибка геометрических параметров блокирует весь build.
Сведения о происхождении и расчётах сохраняются в JSON результата рядом с RFA.

Значения новых независимых геометрических параметров инициализируются по явным
объявлениям во всех существующих типах, чтобы новые тела могли регенерироваться.
В целевых типах применяются явные overrides. Существующие значения других типов
не переписываются, кроме явно разрешённых общих instance-defaults. Формулы исходных параметров могут пересчитаться самим Revit
в ответ на разрешённые записи зависимостей: выражения сохраняются, изменения
результатов перечисляются в `formula_value_recalculations`.

В геометрии box параметры width/depth/height ссылаются на объявления. Габариты
получаются из этих значений/формул; повторные `dimensions_mm`, если заданы,
должны совпасть. Геометрия не выполняет скрытых записей параметров в обход policy.

Все остальные ограничения сохраняются: активное RFA/Revit 2021, dry-run по
умолчанию, свежий context_token, backup, TransactionGroup, отдельный результат,
никаких записей MEP connectors. Геометрия поддерживает box и цилиндр вдоль X,
фиксированные положения отдельных тел и проверку общего габарита сборки.
В формулах допускаются размерные литералы `645 mm` и `45 deg`.

Пример для проверки API: `examples/parameter_policy_preview.json`. Это явно
синтетический dry-run, не спецификация реального оборудования и не команда записи.
